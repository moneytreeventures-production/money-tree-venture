# Production configuration handover

This guide records required configuration names. It does not approve a domain, bucket, secret, deployment or payment mode.

1. Set `APP_URL` to the approved public HTTPS **site origin** (no path, query, credentials or fragment). Use the same origin for production links, SEO metadata and scheduled worker calls. The owner must approve the actual hostname. The current localhost value is suitable only for local development.
2. Create a dedicated **public product-media** R2 bucket and attach the approved HTTPS custom domain to that bucket in Cloudflare R2 settings. Set `PUBLIC_MEDIA_BASE_URL` to that domain's origin. Production rejects `r2.dev`. Do not attach any public domain or enable the `r2.dev` public URL on the private PDF bucket or private staging bucket.
3. Keep `R2_BUCKET_NAME` (private PDF masters and customer copies), `R2_PUBLIC_MEDIA_STAGING_BUCKET_NAME` (private upload staging), and `R2_PUBLIC_MEDIA_BUCKET_NAME` (public product images/videos) distinct. The application rejects equal names, but the owner must separately inspect Cloudflare bucket settings to confirm only the public media bucket has public access. Keep R2 credentials scoped to the buckets and operations each component needs. The custom domain exposes the contents of its attached bucket, so wrong bucket attachment is a **CRITICAL launch blocker**.
4. Configure environment variables in the Netlify UI or another approved secret store, in the correct production deploy context. `APP_URL` and `PUBLIC_MEDIA_BASE_URL` must be present for both build-time URL generation and runtime functions. Server secrets (`MONGODB_URI`, `MONGODB_DB_NAME`, Better Auth/Google credentials, Cashfree credentials, R2 credentials, `RESEND_API_KEY`, `EMAIL_FROM`, `OUTBOX_WORKER_SECRET`) must be available to server functions at runtime and never exposed through `NEXT_PUBLIC_` names or `netlify.toml`. If scoped variables are used, include the Functions scope for scheduled workers and app route functions; include Builds where a value is used during `next build`. Keep sandbox and production deploy contexts separate.
5. Rotate `RESEND_API_KEY` and `OUTBOX_WORKER_SECRET` before any live email delivery; previous diagnostic output exposed their former values. Verify the sender domain in Resend and the worker schedules after deployment. Do not enable order expiration until `ORDER_EXPIRATION_ENABLED` and `ORDER_MAINTENANCE_DATABASE` target the approved database. Confirm Cashfree's production environment and public HTTPS webhook endpoint separately before live transactions.
6. After configuring approved production values, run `npm.cmd run build` and then `npm.cmd run start -- -p 3123` locally in an isolated production-like environment. Confirm startup has no validation error; GET a public page and check expected content, headers and media. Stop the local server afterward. This is a smoke check, not a substitute for deployed Google, Cashfree, R2, email or worker integration tests. Do not use placeholder domains or weaken validation to make it pass.

References: [Cloudflare R2 public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), [Netlify environment scopes](https://docs.netlify.com/build/environment-variables/overview/), [Netlify Functions environment variables](https://docs.netlify.com/build/functions/environment-variables/).
