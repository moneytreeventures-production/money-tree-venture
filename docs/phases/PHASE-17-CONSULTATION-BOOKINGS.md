# Phase 17 ? Consultation bookings (partial implementation)

Checkpoint 2026-11-22. The existing `call_guidance` product, paid-order booking entitlement, Booking model, customer API/account form and owner-only admin API/page were reused. No consultation product, price or duration was invented.

Customer preferred-time PATCH now requires an active booking entitlement, customer-owned paid or refund-processing order and a stored Cashfree SUCCESS payment matching customer, order, amount, currency and environment. The existing booking is created once per purchase by verified-payment fulfillment; `booking_purchase_unique` protects duplicate booking consumption. Requested times are IANA-timezone validated, converted to UTC instants, bounded to one hour through 90 days ahead, and remain requests rather than confirmations. The customer account shows requested and scheduled times without private admin notes. Success feedback now persists while `router.refresh()` updates the account.

Owner management now has distinct awaiting_scheduling ? scheduled ? confirmed ? completed states. Completed and cancelled bookings cannot reopen. Scheduling requires the product-configured duration, a future start and timezone. A transactional write to a single owner scheduling lock serializes competing schedule changes before checking overlap against scheduled and confirmed intervals for that owner. An overlap throws a conflict; no automatic availability or external calendar is claimed. Booking changes retain existing audit records. The existing admin list and private notes remain owner-only. Existing booking-status outbox behavior was not expanded; actual email delivery remains Phase 18.

Focused booking/purchase-route tests 17/17 PASS. TypeScript, test compilation, focused ESLint and git diff --check PASS. No `MONGODB_TEST_URI` is configured; no real Mongo transaction/concurrency, consultation payment, owner/customer browser, schedule or email delivery was verified. No production build was run. No genuine booking or payment record was changed. Client-side admin status filter/search and a dedicated booking detail page are not implemented; the existing account and admin sections show status. The owner still needs to approve availability ownership, cancellation/refund and rescheduling policy. Phase 18 has not started. Prior Phase 14?16 index, concurrency, R2 and authenticated-browser blockers remain.
