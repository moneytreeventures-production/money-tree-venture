## Focused security continuation — 23 November 2026

Confirmed high-risk issue: the initial CSRF guard compared Origin to `request.url`, which can reflect an untrusted Host/forwarded host. It now compares to configured `BETTER_AUTH_URL`, rejects malformed/unconfigured trusted origin when an Origin is supplied, rejects cross-site and same-site Fetch Metadata, and rejects cookie-bearing requests without an Origin or `Sec-Fetch-Site: same-origin`. This policy permits a missing Origin only when the browser supplies same-origin Fetch Metadata, or when there is no cookie (for existing server-side callers). Tests cover same-origin, explicit cross-origin, forged request URL relative to trusted origin, same-site sibling origin, and missing provenance.
