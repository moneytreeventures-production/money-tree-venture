Configure staging variables in the Netlify live/production deploy context used by the published staging branch, including Functions scope and any branch override. Put only owner-approved test inboxes in the comma-separated recipient list. Do not put secrets in browser code.

The send route uses an atomic counter in the existing `supportRates` collection: one attempt per owner per minute and five per UTC day. It refuses to send unless the exact unique rate-counter index is present; a same-named incompatible index is not accepted. ## Configuration checklist

Local `.env.local` needs `MONGODB_URI=<existing development URI>`, `MONGODB_DB_NAME=moneytreeventures`, `EMAIL_TEST_DATABASE_NAME=moneytreeventures`, `EMAIL_TEST_DATABASE_ROLE=local-development-only`, `APP_URL=http://localhost:3000`, and `BETTER_AUTH_URL=http://localhost:3000`. For an authorized test send only, also set `EMAIL_TESTING_ENABLED=true`, `EMAIL_TEST_RECIPIENTS=<owner-approved inbox>`, `RESEND_API_KEY=<private Resend key>`, and `EMAIL_FROM=MoneyTreeVentures <notifications@updates.moneytreeventure.com>`. Never set the local role attestation if that Atlas database is used by a live service or contains real customer transactions. Do not commit these values.

Staging uses the approved HTTPS `APP_URL` and matching `BETTER_AUTH_URL`, `MONGODB_DB_NAME=moneytreeventures_staging`, `EMAIL_TEST_DATABASE_NAME=moneytreeventures_staging`, `EMAIL_TEST_DATABASE_ROLE=staging-only`, `MONGODB_URI=<staging URI>`, `EMAIL_TESTING_ENABLED=true` only during an approved test, `EMAIL_TEST_RECIPIENTS=<owner-approved inbox>`, `RESEND_API_KEY=<private Resend key>`, `EMAIL_FROM=<verified sender>`, and the same `OUTBOX_WORKER_SECRET=<private shared secret>` in both the scheduled Function and Next.js API runtime. Check Netlify deploy context, Functions scope and branch overrides for each key. These are configuration requirements, not evidence that a deployed Function has received them.

`npm.cmd run email:test:resend -- --confirm-database moneytreeventures --recipient <owner-approved inbox>` is a configuration-only dry run; it sends nothing.
